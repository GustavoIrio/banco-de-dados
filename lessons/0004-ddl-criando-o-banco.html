Antes de começar: o que ficou das aulas 1 a 3?

1. Uma chave estrangeira guarda…

  1. um valor que nunca se repete na tabela
  2. o valor da chave primária de outra tabela

É a FK que liga uma tabela à outra e garante a integridade referencial.

SQL e suas quatro partes

Uma linguagem, quatro grupos de comandos.

O mapa do SQL

SiglaNomePara que serveComandosAula
DDLData Definition LanguageDefinir a estruturaCREATE ALTER DROPHoje
DMLData Manipulation LanguageMexer nos dadosINSERT UPDATE DELETE5
DQLData Query LanguageConsultarSELECT5 e 6
DCLData Control LanguageControlar acessoGRANT REVOKE7 (panorama)
DDL mexe na forma (as colunas). DML mexe no conteúdo (as linhas).
DROP TABLE destrói a tabela. DELETE apaga linhas e a tabela continua existindo.

Livro, cap. 11, p. 50–51, 54, 56 e 69. O livro lista o SELECT também dentro da DML (p. 54); as duas classificações são usadas.

CREATE TABLE com restrições

Cada regra do esquema lógico vira uma palavra no SQL.

Anatomia do CREATE TABLE

CREATE TABLE Clientes (
    ClienteID INT AUTO_INCREMENT PRIMARY KEY,
    Nome      VARCHAR(100) NOT NULL,
    CNPJ      CHAR(14)     NOT NULL UNIQUE,
    Endereco  VARCHAR(255),
    Cidade    VARCHAR(100),
    Estado    CHAR(2),
    CEP       CHAR(8),
    Telefone  VARCHAR(20),
    Email     VARCHAR(100)
);

Cada linha: nome da coluna, tipo, restrições. Vírgula entre as colunas, sem vírgula na última.

Digite e, na linha de baixo, acrescente este comando para conferir. Depois clique em Run.

DESCRIBE Clientes;

Livro, cap. 11.1, p. 51 · MySQL: CREATE TABLE

As restrições, uma por uma

RestriçãoO que o SGBD passa a garantirDe onde veio (aula 3)
PRIMARY KEYValor único e nunca NULL; identifica a linha.Chave primária
AUTO_INCREMENTSe você não informar o valor, o SGBD usa o próximo número.Chave substituta
NOT NULLA coluna não pode ficar sem valor.Atributo obrigatório
UNIQUEO valor não se repete (mas não é a PK).Coluna que também não pode repetir (CNPJ, CPF)
DEFAULT valorValor usado quando nada é informado.Regra de negócio
FOREIGN KEYO valor precisa existir na tabela referenciada.Chave estrangeira
Restrição é regra que o banco aplica sempre, não importa qual sistema ou pessoa esteja inserindo o dado. É a "falta de regras" da planilha, resolvida.

Crie Funcionarios e Produtos

 Continue no mesmo script: escreva os dois CREATE TABLE a partir do esquema lógico.

Funcionarios

  • FuncionarioID: PK, automática
  • Nome, Cargo: texto, obrigatórios
  • Salario: dinheiro, obrigatório
  • DataContratacao: data, obrigatória
  • Telefone, Email: texto, opcionais

Produtos

  • ProdutoID: PK, automática
  • Nome: texto, obrigatório
  • Descricao: texto longo, opcional
  • Preco: dinheiro, obrigatório
  • Estoque: inteiro, obrigatório, começa em 0
CREATE TABLE Funcionarios (
    FuncionarioID   INT AUTO_INCREMENT PRIMARY KEY,
    Nome            VARCHAR(100)  NOT NULL,
    Cargo           VARCHAR(50)   NOT NULL,
    Salario         DECIMAL(10,2) NOT NULL,
    DataContratacao DATE          NOT NULL,
    Telefone        VARCHAR(20),
    Email           VARCHAR(100)
);

CREATE TABLE Produtos (
    ProdutoID INT AUTO_INCREMENT PRIMARY KEY,
    Nome      VARCHAR(100)  NOT NULL,
    Descricao TEXT,
    Preco     DECIMAL(10,2) NOT NULL,
    Estoque   INT           NOT NULL DEFAULT 0
);
Bloco 3 · 40 min

Chaves estrangeiras em SQL

Agora as tabelas que dependem das outras.

Vendas: duas chaves estrangeiras

CREATE TABLE Vendas (
    VendaID       INT AUTO_INCREMENT PRIMARY KEY,
    ClienteID     INT           NOT NULL,
    FuncionarioID INT           NULL,       -- NULL = venda feita pelo site
    DataVenda     DATE          NOT NULL,
    TotalVenda    DECIMAL(10,2) NOT NULL,
    CONSTRAINT fk_vendas_cliente
        FOREIGN KEY (ClienteID) REFERENCES Clientes(ClienteID),
    CONSTRAINT fk_vendas_funcionario
        FOREIGN KEY (FuncionarioID) REFERENCES Funcionarios(FuncionarioID)
);

Leia assim: "a coluna ClienteID desta tabela referencia a coluna ClienteID da tabela Clientes".

  • A coluna da FK tem o mesmo tipo da PK que ela referencia (INT com INT).
  • CONSTRAINT nome dá um nome à regra. Ajuda a ler os erros e a remover depois.

Livro, p. 44 · MySQL: Foreign Keys

Dois cuidados com FK no MySQL

1 · A ordem importa

Só dá para referenciar uma tabela que já existe.

Ordem de criação da AutoNex:

  1. Clientes, Funcionarios, Produtos (não dependem de ninguém)
  2. Vendas (depende de Clientes e Funcionarios)
2 · Escreva FOREIGN KEY por extenso

Esta forma curta parece funcionar, mas no MySQL não cria regra nenhuma:

ClienteID INT REFERENCES Clientes(ClienteID)

O comando roda sem erro e a FK simplesmente não existe. Use sempre FOREIGN KEY (...) REFERENCES ... em linha separada.

MySQL: Foreign Key Differences. Testado no MySQL 8.4 do OneCompiler: a forma curta aceita qualquer valor.

Crie Turmas e Alunos

 Outro problema, outro script: abra o OneCompiler em uma nova aba.

"Uma turma tem vários alunos; cada aluno está em uma turma só."

TURMAS1 temN ALUNOS
  • Turmas: TurmaID (PK, automática), Nome (obrigatório), Turno (opcional)
  • Alunos: AlunoID (PK, automática), Nome (obrigatório), Matricula (obrigatória, não se repete)
  • Em qual tabela fica a FK?
  • Qual tabela você cria primeiro?
  • No fim, acrescente SHOW TABLES; e confira se aparecem as duas.
CREATE TABLE Turmas (
    TurmaID INT AUTO_INCREMENT PRIMARY KEY,
    Nome    VARCHAR(20) NOT NULL,
    Turno   VARCHAR(10)
);

CREATE TABLE Alunos (
    AlunoID   INT AUTO_INCREMENT PRIMARY KEY,
    TurmaID   INT          NOT NULL,
    Nome      VARCHAR(100) NOT NULL,
    Matricula CHAR(6)      NOT NULL UNIQUE,
    CONSTRAINT fk_alunos_turma
        FOREIGN KEY (TurmaID) REFERENCES Turmas(TurmaID)
);

SHOW TABLES;

A FK fica em Alunos, o lado N. Turmas vem primeiro, porque Alunos depende dela.

Na volta: mudar o que já existe

O cliente sempre lembra de mais um campo depois que o banco está pronto.

ALTER TABLE: mudando a estrutura

Adicionar coluna

ALTER TABLE Funcionarios
ADD DataNascimento DATE;

Mudar o tipo de uma coluna

ALTER TABLE Clientes
MODIFY Telefone VARCHAR(30);

Remover coluna

ALTER TABLE Funcionarios
DROP COLUMN DataNascimento;

Adicionar uma FK depois

ALTER TABLE Vendas
ADD CONSTRAINT fk_vendas_cliente
FOREIGN KEY (ClienteID)
    REFERENCES Clientes(ClienteID);
O que acontece com as linhas que já existem? Em ADD, a coluna nova entra com NULL em todas. Em DROP COLUMN, os dados daquela coluna são perdidos.

Livro, cap. 11.1, p. 52–53. MODIFY é sintaxe do MySQL/MariaDB; outros SGBDs usam ALTER COLUMN.

DROP TABLE e a ordem inversa

Tente apagar Clientes:

DROP TABLE Clientes;
ERROR 3730: Cannot drop table 'clientes'
referenced by a foreign key constraint
'fk_vendas_cliente' on table 'vendas'.

O SGBD protege a integridade referencial: se Clientes sumisse, para onde apontaria o ClienteID de Vendas?

Para apagar tudo, a ordem é a inversa da criação: primeiro quem depende, depois quem é referenciado.

DROP TABLE IF EXISTS Vendas;
DROP TABLE IF EXISTS Produtos;
DROP TABLE IF EXISTS Funcionarios;
DROP TABLE IF EXISTS Clientes;
DROP não tem desfazer. Em banco de empresa, só depois de conferir o backup. Aqui, apague do script o DROP que deu erro e não acrescente este bloco.

Livro, cap. 11.1, p. 53.

O cliente mudou de ideia

 Três pedidos do dono da AutoNex. Um ALTER TABLE para cada.

  1. "Quero guardar o peso em quilos de cada produto, com 3 casas decimais." (coluna PesoKg)
  2. "O nome de alguns produtos não cabe. Aumente para 150 caracteres." (mantenha obrigatório)
  3. "Esquece o peso, não vamos usar."

Acrescente um por vez no script, com DESCRIBE Produtos; depois de cada um, e confira.

ALTER TABLE Produtos ADD PesoKg DECIMAL(8,3);

ALTER TABLE Produtos MODIFY Nome VARCHAR(150) NOT NULL;

ALTER TABLE Produtos DROP COLUMN PesoKg;

No 2, se esquecer o NOT NULL, a coluna volta a aceitar NULL: o MODIFY redefine a coluna inteira.

Prova de fogo: as regras funcionam?

Acrescente um por vez no fim do script, clique em Run e leia a resposta. Deu erro? Apague esse comando antes de testar o próximo, porque o Run para nele.

-- 1. Um cliente válido
INSERT INTO Clientes (Nome, CNPJ, Cidade, Estado)
VALUES ('BS Serviços Automotivos ME', '48996633000128', 'Bauru', 'SP');

-- 2. Mesmo CNPJ de novo
INSERT INTO Clientes (Nome, CNPJ) VALUES ('Outra Empresa', '48996633000128');

-- 3. Cliente sem nome
INSERT INTO Clientes (CNPJ) VALUES ('11222000133');

-- 4. Venda para um cliente que não existe
INSERT INTO Vendas (ClienteID, DataVenda, TotalVenda)
VALUES (99, '2024-07-01', 100.00);

1 funciona; o ClienteID 1 foi gerado pelo AUTO_INCREMENT.
2 recusado pelo UNIQUE (entrada duplicada para a chave clientes.CNPJ).
3 recusado pelo NOT NULL (o campo Nome não tem valor padrão).
4 recusado pela FOREIGN KEY (fk_vendas_cliente): não existe cliente 99.

Revisão relâmpago

1. Qual comando pertence à DDL?

  1. INSERT
  2. SELECT
  3. ALTER
DDL define estrutura: CREATE, ALTER, DROP.

2. Qual tabela da AutoNex precisa ser criada por último?

  1. Clientes
  2. Funcionarios
  3. Vendas
Ela referencia Clientes e Funcionarios, que precisam existir antes.

3. Qual restrição impede dois clientes com o mesmo CNPJ?

  1. NOT NULL
  2. UNIQUE
  3. DEFAULT
UNIQUE: o valor não se repete, sem ser a chave primária.
