INNER JOIN

A chave estrangeira é a ponte. O JOIN é atravessar a ponte.

O gerente quer ver o nome do cliente, não o número.

O nome está em outra tabela. Foi a normalização que o colocou lá (e com razão). Precisamos de uma consulta que leia as duas e case as linhas.

INNER JOIN: casando linhas

SELECT Vendas.VendaID, Clientes.Nome, Vendas.DataVenda, Vendas.TotalVenda
FROM Vendas
INNER JOIN Clientes ON Vendas.ClienteID = Clientes.ClienteID;
VendaIDNomeDataVendaTotalVenda
1BS Serviços Automotivos ME2024-03-041477.80
2Auto Peças Curitiba Ltda2024-03-116100.50
3Mecânica do Ademar2024-04-02379.80
… 8 linhas no total
  • FROM Vendas INNER JOIN Clientes — as duas tabelas da consulta.
  • ON … — a condição de junção: quase sempre FK = PK.
  • Tabela.Coluna — as duas têm ClienteID; o prefixo diz de qual estamos falando.

Livro, cap. 11.3, p. 58–60. JOIN sozinho é o mesmo que INNER JOIN · MariaDB: Joining Tables

E se eu esquecer o ON?

SELECT Vendas.VendaID, Clientes.Nome
FROM Vendas
JOIN Clientes;

Resultado: 48 linhas.

Sem condição, o SGBD combina cada venda com cada cliente: 8 × 6. É o produto cartesiano.

O ON fica só com as combinações que fazem sentido: aquelas em que o ClienteID da venda é o do cliente.

Como o JOIN "pensa"
  1. Pega uma linha de Vendas.
  2. Procura em Clientes as linhas que satisfazem o ON.
  3. Para cada uma que achar, monta uma linha de resultado com as colunas das duas.
  4. Repete para a próxima venda.
Apareceram muito mais linhas do que você esperava? Quase sempre é ON faltando ou errado.

Apelidos de tabela

Repetir Vendas. e Clientes. cansa. Damos um alias a cada tabela:

SELECT V.VendaID,
       C.Nome AS Cliente,
       V.DataVenda,
       V.TotalVenda
FROM Vendas V
JOIN Clientes C ON V.ClienteID = C.ClienteID
WHERE C.Estado = 'PR'
ORDER BY V.DataVenda;
  • Vendas V — dentro desta consulta, Vendas se chama V.
  • C.Nome AS Cliente — alias de coluna: muda o título no resultado.
  • WHERE e ORDER BY continuam funcionando, e podem usar colunas de qualquer uma das tabelas.

Esta consulta traz 6 linhas: as vendas para clientes do Paraná.

Seus primeiros JOINs

 Duas tabelas por consulta. Antes de digitar, diga: qual FK liga as duas?

  1. Número da venda, data e nome do funcionário que vendeu. Quantas linhas vieram? Por quê?
  2. Os itens da venda 4: nome do produto, quantidade e preço unitário.
  3. Número, nome do cliente e total das vendas para clientes de Curitiba.
  4. Nome do produto, quantidade e subtotal (quantidade × preço unitário) de todos os itens, do maior subtotal para o menor.
SELECT V.VendaID, V.DataVenda, F.Nome AS Funcionario
FROM Vendas V JOIN Funcionarios F ON V.FuncionarioID = F.FuncionarioID;
-- 7 linhas: a venda 6 tem FuncionarioID NULL e não casa com ninguém

SELECT P.Nome, I.Quantidade, I.PrecoUnitario
FROM ItensVenda I JOIN Produtos P ON I.ProdutoID = P.ProdutoID
WHERE I.VendaID = 4;
-- Bateria 60Ah (6 × 620.00) e Amortecedor traseiro (4 × 430.00)

SELECT V.VendaID, C.Nome, V.TotalVenda
FROM Vendas V JOIN Clientes C ON V.ClienteID = C.ClienteID
WHERE C.Cidade = 'Curitiba';
-- vendas 2, 3, 4 e 8

SELECT P.Nome, I.Quantidade, I.Quantidade * I.PrecoUnitario AS Subtotal
FROM ItensVenda I JOIN Produtos P ON I.ProdutoID = P.ProdutoID
ORDER BY Subtotal DESC;
-- 13 linhas; a primeira é Correia de distribuição, 5120.50

Um JOIN de cada vez, seguindo as chaves estrangeiras.

Siga o caminho no esquema: cada seta é um JOIN … ON FK = PK.

SELECT V.VendaID,
       C.Nome AS Cliente,
       F.Nome AS Funcionario,
       P.Nome AS Produto,
       I.Quantidade,
       I.PrecoUnitario
FROM Vendas V
JOIN Clientes     C ON V.ClienteID     = C.ClienteID
JOIN Funcionarios F ON V.FuncionarioID = F.FuncionarioID
JOIN ItensVenda   I ON I.VendaID       = V.VendaID
JOIN Produtos     P ON I.ProdutoID     = P.ProdutoID
WHERE V.VendaID = 2
ORDER BY P.Nome;

Receita para escrever um JOIN grande

  1. Quais colunas o resultado precisa mostrar? Anote em que tabela cada uma mora.
  2. Trace o caminho entre essas tabelas no esquema, pelas FKs. Tabelas "de passagem" entram também.
  3. Escreva o FROM com uma tabela e um JOIN por seta.
  4. Rode com SELECT * e poucas linhas (WHERE numa venda só). Confira no olho.
  5. Só então troque o * pelas colunas, ponha alias, WHERE e ORDER BY definitivos.
Tabela de passagem "Quais clientes compraram bateria?" Quero só Clientes e Produtos, mas não existe FK entre eles. O caminho passa por Vendas e ItensVenda: são quatro tabelas no FROM, mesmo mostrando colunas de duas.

7 linhas. A venda 6 (R$ 700,00, feita pelo site) não aparece.

Ela tem FuncionarioID NULL. NULL não é igual a nada, então o ON nunca fica verdadeiro para ela.

O INNER JOIN só devolve linhas que têm par dos dois lados. Se o gerente somar esse relatório, vão faltar R$ 700,00.

LEFT JOIN: traz todas as linhas da tabela da esquerda (a que vem antes da palavra JOIN). Onde não houver par, as colunas da direita vêm com NULL.

"Esquerda" é posição no texto FROM Vendas LEFT JOIN Funcionarios
Esquerda = Vendas. Todas as vendas aparecem.

Livro, cap. 11.3, p. 62–63. LEFT OUTER JOIN é o mesmo comando por extenso.

RIGHT JOIN e o que não existe aqui

JunçãoDevolveNo MariaDB
INNER JOINSó as linhas com par dos dois lados.✔
LEFT JOINTodas da esquerda + par da direita, ou NULL.✔
RIGHT JOINTodas da direita + par da esquerda, ou NULL.✔
FULL OUTER JOINTodas das duas, com NULL onde faltar par.✘ não existe

Estas duas consultas dão o mesmo resultado:

FROM Funcionarios F LEFT JOIN Vendas V ON …

FROM Vendas V RIGHT JOIN Funcionarios F ON …
Na prática, quase todo mundo escreve só LEFT JOIN e escolhe qual tabela vem primeiro. É mais fácil de ler: "tudo desta, mais o que houver daquela".

Livro, cap. 11.3, p. 62–64 · MariaDB: JOIN Syntax (a gramática lista INNER, CROSS, LEFT, RIGHT e NATURAL).

Quem ficou de fora?

 Para cada item, decida primeiro: qual tabela precisa aparecer inteira? Ela vai à esquerda.

  1. Todos os clientes e o número de cada venda que fizeram. Quem não comprou deve aparecer também.
  2. Só os clientes que nunca compraram.
  3. Produtos que nunca foram vendidos.
  4. Todas as vendas com o nome do cliente e do funcionário, sem perder a venda 6.
SELECT C.Nome, V.VendaID
FROM Clientes C LEFT JOIN Vendas V ON V.ClienteID = C.ClienteID
ORDER BY C.Nome;                                   -- 9 linhas

SELECT C.Nome
FROM Clientes C LEFT JOIN Vendas V ON V.ClienteID = C.ClienteID
WHERE V.VendaID IS NULL;                           -- Centro Automotivo Joinville

SELECT P.Nome
FROM Produtos P LEFT JOIN ItensVenda I ON I.ProdutoID = P.ProdutoID
WHERE I.ItemVendaID IS NULL;                       -- Palheta limpador

SELECT V.VendaID, C.Nome AS Cliente, F.Nome AS Funcionario
FROM Vendas V
JOIN Clientes C ON V.ClienteID = C.ClienteID
LEFT JOIN Funcionarios F ON V.FuncionarioID = F.FuncionarioID
ORDER BY V.VendaID;                                -- 8 linhas

No item 4, o JOIN com Clientes pode ser INNER (toda venda tem cliente); só o de Funcionarios precisa ser LEFT.

CASE, IN e EXISTS

Três ferramentas que o livro traz para deixar a consulta mais inteligente.

CASE: um if dentro do SELECT

SELECT V.VendaID,
       C.Nome AS Cliente,
       V.TotalVenda,
       CASE
           WHEN V.TotalVenda < 1000 THEN 'Pequena'
           WHEN V.TotalVenda BETWEEN 1000 AND 5000 THEN 'Média'
           ELSE 'Grande'
       END AS CategoriaVenda
FROM Vendas V
JOIN Clientes C ON V.ClienteID = C.ClienteID
ORDER BY V.VendaID;
  • As cláusulas WHEN são testadas de cima para baixo; vale a primeira verdadeira.
  • ELSE pega o que sobrou. Começa com CASE, termina com END.

Subconsulta: um SELECT dentro do outro

IN com subconsulta — a lista vem de outra consulta:

SELECT Nome
FROM Clientes
WHERE ClienteID IN (
    SELECT ClienteID
    FROM Vendas
    WHERE TotalVenda > 5000
);

A consulta de dentro devolve o ClienteID 2 (duas vezes: vendas 2 e 4); a de fora mostra o nome: Auto Peças Curitiba Ltda.

EXISTS — verdadeiro se a subconsulta devolver pelo menos uma linha:

SELECT C.Nome
FROM Clientes C
WHERE EXISTS (
    SELECT 1
    FROM Vendas V
    WHERE V.ClienteID = C.ClienteID
      AND V.TotalVenda > 5000
);

Mesmo resultado. Repare: a subconsulta usa C.ClienteID, da consulta de fora. Ela é avaliada para cada cliente.

Livro, cap. 11.3, p. 64–66. Um JOIN com DISTINCT chega ao mesmo resultado: em SQL quase sempre há mais de um caminho.

Desafio: perguntas do dono da AutoNex

 Em dupla. Use a receita: colunas → caminho → JOINs → conferir.

  1. "Quais clientes já compraram Bateria 60Ah?" (sem repetir nomes)
  2. "Quero a lista de todas as vendas com o nome do vendedor; quando for pelo site, escreva 'Site'."
  3. "De cada item vendido: produto, subtotal e a etiqueta 'Alto' se o subtotal passar de R$ 1.000,00, senão 'Normal'."
  4. "Quais clientes do Paraná foram atendidos pela Agata Silva?"
SELECT DISTINCT C.Nome
FROM Clientes C
JOIN Vendas     V ON V.ClienteID = C.ClienteID
JOIN ItensVenda I ON I.VendaID   = V.VendaID
JOIN Produtos   P ON I.ProdutoID = P.ProdutoID
WHERE P.Nome = 'Bateria 60Ah';
-- Auto Peças Curitiba Ltda, Mecânica do Ademar

SELECT V.VendaID, V.DataVenda,
       CASE WHEN F.Nome IS NULL THEN 'Site' ELSE F.Nome END AS Vendedor
FROM Vendas V LEFT JOIN Funcionarios F ON V.FuncionarioID = F.FuncionarioID
ORDER BY V.VendaID;                                    -- 8 linhas; a 6 é 'Site'

SELECT P.Nome, I.Quantidade * I.PrecoUnitario AS Subtotal,
       CASE WHEN I.Quantidade * I.PrecoUnitario > 1000 THEN 'Alto' ELSE 'Normal' END AS Etiqueta
FROM ItensVenda I JOIN Produtos P ON I.ProdutoID = P.ProdutoID;
-- 13 linhas; 5 com 'Alto'

SELECT DISTINCT C.Nome
FROM Clientes C
JOIN Vendas       V ON V.ClienteID     = C.ClienteID
JOIN Funcionarios F ON V.FuncionarioID = F.FuncionarioID
WHERE C.Estado = 'PR' AND F.Nome = 'Agata Silva';      -- Mecânica do Ademar

Revisão relâmpago

1. Na condição ON de um JOIN, normalmente comparamos…

  1. duas chaves primárias
  2. uma FK com uma PK
  3. dois nomes de tabela
A FK de uma tabela com a PK da tabela que ela referencia.

2. FROM Produtos P LEFT JOIN ItensVenda I ON … garante que aparecem todos os…

  1. itens de venda
  2. produtos
  3. pares casados
A tabela da esquerda (antes do JOIN) aparece inteira.

3. Um JOIN devolveu 48 linhas quando você esperava 8. O que provavelmente houve?

  1. Faltou o ORDER BY no final
  2. Faltou ou errou o ON
  3. Faltou o alias das tabelas
Produto cartesiano: cada linha combinada com todas da outra tabela.
