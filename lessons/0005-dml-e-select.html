INSERT: colocando dados

As cinco tabelas existem. Estão vazias.

INSERT com lista de colunas

INSERT INTO Produtos (Nome, Descricao, Preco, Estoque)
VALUES ('Correia de distribuição',
        'Correia dentada que sincroniza o motor', 512.05, 200);
  • Não informamos ProdutoID: o AUTO_INCREMENT gera.
  • A ordem dos valores segue a ordem da lista de colunas, não a da tabela.
  • Texto e data entre aspas simples: '2024-03-04'. Número sem aspas, com ponto decimal.
Sempre escreva a lista de colunas Sem a lista, o SGBD espera um valor para todas as colunas, na ordem da tabela, inclusive o ID. Faltou um? Erro de contagem de colunas.

Livro, cap. 11.2, p. 55 · MariaDB: INSERT

SELECT: fazendo perguntas

Guardar dado é metade do trabalho. A outra metade é achar o que interessa.

A estrutura de uma consulta

SELECT coluna1, coluna2      -- o que eu quero ver
FROM tabela                  -- de onde
WHERE condição               -- quais linhas
ORDER BY coluna;             -- em que ordem
SELECT Nome, Cidade
FROM Clientes
WHERE Estado = 'PR'
ORDER BY Nome;

Na volta: filtros mais espertos

E depois, os dois comandos mais perigosos do SQL.

BETWEEN, IN e LIKE

Faixa de valores

SELECT Nome, Preco
FROM Produtos
WHERE Preco
  BETWEEN 100 AND 500;

Inclui os extremos. Traz Pneu X, Pastilha e Amortecedor.

Lista de valores

SELECT Nome, Cargo
FROM Funcionarios
WHERE Cargo IN
  ('Vendedor',
   'Vendedora');

Equivale a vários OR. Traz Agata, Joaquim e Carmen.

Pedaço de texto

SELECT Nome
FROM Produtos
WHERE Nome
  LIKE 'P%';

Começa com P: Pneu X, Pastilha e Palheta.

Padrão do LIKEEncontra
'P%'começa com P  (% = qualquer sequência, inclusive vazia)
'%freio%'contém "freio" em qualquer posição
'%.com.br'termina com .com.br
'_ateria%'um caractere qualquer, depois "ateria"  (_ = exatamente um)

Livro, cap. 11.3, p. 64–65 · MariaDB: LIKE. No nosso banco, comparações de texto não diferenciam maiúsculas de minúsculas: 'curitiba' encontra 'Curitiba'.

  • ASC (crescente) é o padrão; DESC inverte. O contrário de IS NULL é IS NOT NULL.

DISTINCT elimina linhas repetidas do resultado. Sem ele, Curitiba apareceria duas vezes.

Os 3 produtos mais caros

FROM Produtos

LIMIT 3;

LIMIT n corta o resultado nas primeiras n linhas. Só faz sentido junto com ORDER BY.

DISTINCT e LIMIT não estão no livro; entram aqui porque aparecem em quase toda consulta do dia a dia. LIMIT é sintaxe do MySQL/MariaDB.

Filtros combinados

 Em dupla: um digita, o outro confere. Troquem a cada questão.

  1. Produtos com estoque entre 100 e 500 unidades, do maior estoque para o menor.
  2. Clientes cujo e-mail termina com .com.br e que não são do Paraná.
  3. Vendas que não tiveram funcionário (vendas pelo site).
  4. Funcionários contratados antes de 2021, do mais antigo para o mais novo.
  5. Produtos que têm "freio" ou "óleo" no nome.
  6. A venda de maior valor (só ela).
SELECT Nome, Estoque FROM Produtos
WHERE Estoque BETWEEN 100 AND 500 ORDER BY Estoque DESC;        -- 4 linhas

SELECT Nome, Email FROM Clientes
WHERE Email LIKE '%.com.br' AND Estado <> 'PR';                 -- 2 linhas

SELECT * FROM Vendas WHERE FuncionarioID IS NULL;               -- 1 linha (venda 6)

SELECT Nome, DataContratacao FROM Funcionarios
WHERE DataContratacao < '2021-01-01' ORDER BY DataContratacao;  -- Ruan, Agata

SELECT Nome FROM Produtos
WHERE Nome LIKE '%freio%' OR Nome LIKE '%óleo%';                -- 2 linhas

SELECT * FROM Vendas ORDER BY TotalVenda DESC LIMIT 1;          -- venda 2

UPDATE e DELETE

Dois comandos que fazem exatamente o que você escreveu. Mesmo que não seja o que você queria.

UPDATE: alterar linhas que já existem

UPDATE Produtos
SET Preco = 550.25
WHERE ProdutoID = 1;

Várias colunas de uma vez:

UPDATE Clientes
SET Telefone = '4430251100',
    Email = 'contato@retifica.com.br'
WHERE ClienteID = 5;

Usando o valor atual na conta (aumento de 10%):

UPDATE Funcionarios
SET Salario = Salario * 1.10
WHERE Cargo = 'Estagiária';
O WHERE decide quem muda UPDATE Produtos SET Preco = 550.25;  sem WHERE coloca o mesmo preço em todos os produtos. O SGBD não pergunta "tem certeza?".

Livro, cap. 11.2, p. 55 · MariaDB: UPDATE

DELETE: apagar linhas

DELETE FROM Produtos
WHERE ProdutoID = 8;

A Palheta limpador nunca foi vendida: o DELETE funciona.

DELETE FROM Clientes
WHERE ClienteID = 1;
Erro: não é possível excluir — a linha é
referenciada por Vendas (fk_vendas_cliente)

A BS Serviços tem vendas. A FK protege o histórico.

Mesma regra do UPDATE DELETE FROM Produtos;  sem WHERE apaga todas as linhas.
Hábito profissional

Antes de todo UPDATE ou DELETE, rode um SELECT com o mesmo WHERE.

SELECT * FROM Produtos WHERE ProdutoID = 8;
-- é só essa linha mesmo? então:
DELETE FROM Produtos WHERE ProdutoID = 8;

Manutenção na AutoNex

 Para cada item: primeiro o SELECT de conferência, depois o comando.

  1. O Filtro de óleo passou a custar R$ 42,50.
  2. A Oficina Fernanda & Filhos informou o e-mail contato@fernandaefilhos.com.br.
  3. Chegaram 30 amortecedores traseiros: some ao estoque atual.
  4. O Centro Automotivo Joinville pediu para sair do cadastro. Dá para apagar? Por quê?
  5. O funcionário Joaquim Silveira saiu da empresa. Dá para apagar? O que você faria?
UPDATE Produtos SET Preco = 42.50 WHERE ProdutoID = 3;

UPDATE Clientes SET Email = 'contato@fernandaefilhos.com.br' WHERE ClienteID = 4;

UPDATE Produtos SET Estoque = Estoque + 30 WHERE ProdutoID = 6;   -- vai de 12 para 42

DELETE FROM Clientes WHERE ClienteID = 6;   -- funciona: nenhuma venda aponta para ele

DELETE FROM Funcionarios WHERE FuncionarioID = 2;   -- recusado: ele tem 2 vendas

No item 5 não se apaga: o histórico de vendas depende dele. Solução comum: uma coluna Ativo ou DataDesligamento em Funcionarios.

Desafio: o relatório do gerente

 Antes, reimporte o autonex.sql para voltar aos dados originais. Depois responda cada pedido com uma consulta.

  1. "Quais produtos preciso repor?" — nome e estoque dos produtos com menos de 50 unidades, do menor estoque para o maior.
  2. "Quanto dinheiro tenho parado?" — nome e valor em estoque (preço × estoque) dos 3 produtos com maior valor parado.
  3. "Quem são meus vendedores?" — nome e salário de quem tem cargo começando com "Vend", do maior salário para o menor.
  4. "Quais vendas do segundo trimestre de 2024 passaram de R$ 700,00?" — número, data e total, em ordem de data.
SELECT Nome, Estoque FROM Produtos WHERE Estoque < 50 ORDER BY Estoque;
-- Palheta 0, Amortecedor 12, Bateria 40

SELECT Nome, Preco * Estoque AS ValorParado FROM Produtos
ORDER BY ValorParado DESC LIMIT 3;
-- Correia 102410.00, Pneu X 35000.00, Pastilha 28485.00

SELECT Nome, Salario FROM Funcionarios
WHERE Cargo LIKE 'Vend%' ORDER BY Salario DESC;
-- Agata 3200, Carmen 3100, Joaquim 2900

SELECT VendaID, DataVenda, TotalVenda FROM Vendas
WHERE DataVenda BETWEEN '2024-04-01' AND '2024-06-30' AND TotalVenda > 700
ORDER BY DataVenda;
-- vendas 4, 5 e 7

Revisão relâmpago

1. O que faz DELETE FROM Vendas; ?

  1. Apaga a tabela Vendas do banco
  2. Apaga todas as linhas de Vendas
  3. Apaga somente a última linha inserida
Sem WHERE, vale para todas as linhas. A tabela continua existindo, vazia. (Aqui o SGBD recusaria por causa de ItensVenda.)

2. Qual padrão encontra nomes que contêm "auto"?

  1. LIKE 'auto%'
  2. LIKE '%auto%'
  3. LIKE '_auto_'
% dos dois lados: qualquer coisa antes e depois.

3. Qual cláusula garante a ordem das linhas no resultado?

  1. WHERE
  2. DISTINCT
  3. ORDER BY
Sem ORDER BY, o SGBD devolve na ordem que quiser.
