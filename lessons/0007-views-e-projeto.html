Bloco 1 · 40 min

Views

Aquele JOIN de cinco tabelas deu trabalho. Vamos guardá-lo.

O problema: reescrever sempre a mesma consulta

SELECT V.VendaID, V.DataVenda, C.Nome AS Cliente, C.Cidade,
       F.Nome AS Funcionario, P.Nome AS Produto,
       I.Quantidade, I.PrecoUnitario,
       I.Quantidade * I.PrecoUnitario AS Subtotal
FROM Vendas V
JOIN Clientes          C ON V.ClienteID     = C.ClienteID
LEFT JOIN Funcionarios F ON V.FuncionarioID = F.FuncionarioID
JOIN ItensVenda        I ON I.VendaID       = V.VendaID
JOIN Produtos          P ON I.ProdutoID     = P.ProdutoID;

O setor financeiro quer isso filtrado por cliente. O comercial, por vendedor. O estoque, por produto.

Três pessoas, a mesma junção, três chances de errar o ON.

CREATE VIEW: uma consulta com nome

CREATE VIEW vw_VendasDetalhadas AS
SELECT V.VendaID, V.DataVenda, C.Nome AS Cliente, C.Cidade,
       F.Nome AS Funcionario, P.Nome AS Produto,
       I.Quantidade, I.PrecoUnitario,
       I.Quantidade * I.PrecoUnitario AS Subtotal
FROM Vendas V
JOIN Clientes          C ON V.ClienteID     = C.ClienteID
LEFT JOIN Funcionarios F ON V.FuncionarioID = F.FuncionarioID
JOIN ItensVenda        I ON I.VendaID       = V.VendaID
JOIN Produtos          P ON I.ProdutoID     = P.ProdutoID;

Uma view (visão) é uma consulta armazenada que se comporta como uma tabela virtual.

  • Ela não guarda dados: guarda o SELECT. Cada vez que é consultada, lê as tabelas de verdade.
  • Vendeu mais um item? A view já mostra, sem precisar atualizar nada.

Livro, cap. 13, p. 77 · MariaDB: CREATE VIEW

Para que servem as views

Simplificar Esconde junções complicadas. Quem consulta não precisa conhecer as cinco tabelas.
Padronizar A regra (o ON, o cálculo do subtotal) fica escrita uma vez. Todos os relatórios usam a mesma.
Proteger Mostra só algumas colunas. Dá para liberar a view para um usuário sem liberar a tabela. 
-- Uma lista de ramais que não expõe salário nem data de contratação
CREATE VIEW vw_ContatosFuncionarios AS
SELECT Nome, Cargo, Telefone, Email
FROM Funcionarios;
Cuidado: view não deixa a consulta mais rápida. Ela executa o SELECT inteiro a cada uso. View em cima de view em cima de view pode ficar lenta e difícil de entender.

Livro, cap. 13, p. 77–78.

Crie duas views na AutoNex

 Crie a vw_VendasDetalhadas do slide e depois:

  1. vw_EstoqueBaixo: nome, preço e estoque dos produtos com menos de 50 unidades.
  2. vw_VendasResumo: número da venda, data, nome do cliente, nome do vendedor (ou 'Site') e total. Uma linha por venda.
  3. Usando só a vw_VendasResumo: liste as vendas feitas pelo site.
  4. Faça UPDATE Produtos SET Estoque = 5 WHERE ProdutoID = 1; e consulte de novo a vw_EstoqueBaixo. O que mudou? Por quê?
CREATE VIEW vw_EstoqueBaixo AS
SELECT Nome, Preco, Estoque FROM Produtos WHERE Estoque < 50;

CREATE VIEW vw_VendasResumo AS
SELECT V.VendaID, V.DataVenda, C.Nome AS Cliente,
       CASE WHEN F.Nome IS NULL THEN 'Site' ELSE F.Nome END AS Vendedor,
       V.TotalVenda
FROM Vendas V
JOIN Clientes C ON V.ClienteID = C.ClienteID
LEFT JOIN Funcionarios F ON V.FuncionarioID = F.FuncionarioID;

SELECT * FROM vw_VendasResumo WHERE Vendedor = 'Site';   -- venda 6

No item 4, a Correia de distribuição passa a aparecer na vw_EstoqueBaixo (eram 3 linhas, viram 4). A view não guarda dados: relê a tabela a cada consulta.

Procedures e triggers: código dentro do banco

Procedure: um bloco de comandos SQL com nome e parâmetros, guardado no banco e executado com CALL.

DELIMITER //
CREATE PROCEDURE VendasDoCliente(IN pClienteID INT)
BEGIN
    SELECT VendaID, DataVenda, TotalVenda
    FROM Vendas
    WHERE ClienteID = pClienteID;
END //
DELIMITER ;

CALL VendasDoCliente(2);

Livro, cap. 12, p. 72–76.

Trigger (gatilho): código que o SGBD dispara sozinho antes ou depois de um INSERT, UPDATE ou DELETE.

CREATE TRIGGER trg_baixa_estoque
AFTER INSERT ON ItensVenda
FOR EACH ROW
    UPDATE Produtos
    SET Estoque = Estoque - NEW.Quantidade
    WHERE ProdutoID = NEW.ProdutoID;

Vendeu um item, o estoque baixa automaticamente.

Livro, cap. 14, p. 79–80.

Os dois colocam regra de negócio dentro do banco: vale para qualquer sistema que acesse, mas fica "escondida" e mais difícil de manter.

No laboratório usamos root sem senha. Em produção, isso nunca acontece.

Livro, cap. 11.4, p. 69–70.

Big Data e NoSQL

Big Data: volumes de dados grandes demais para as ferramentas tradicionais. Os 5 Vs: Volume, Velocidade, Variedade, Veracidade, Valor.

NoSQL: bancos não relacionais, criados para escalar em muitos servidores e aceitar dados sem esquema fixo.

ModeloGuardaExemplo
Chave-valorpares simplesRedis

Não é substituição Sistema de vendas, financeiro, RH: relacional continua sendo a escolha padrão. NoSQL entra quando o volume ou a variedade dos dados pede. Muitas empresas usam os dois.

Livro, cap. 15 e 16, p. 81–92 (Sadalage & Fowler, 2013). Cassandra e Neo4j são exemplos acrescentados; o livro cita Redis, DynamoDB, MongoDB e CouchDB.

Na volta: o projeto integrador

Tudo o que fizemos em seis aulas, em um problema novo, sozinho.

Projeto integrador: TecnoCursos

"A TecnoCursos oferece cursos livres de tecnologia. Cada curso tem nome, carga horária e valor. Um curso é oferecido em várias turmas; cada turma tem data de início, turno (manhã, tarde ou noite) e é ministrada por um instrutor. Dos instrutores guardamos nome, e-mail e especialidade; um instrutor pode ministrar várias turmas. Os alunos têm nome, CPF, e-mail e telefone (opcional). Um aluno pode se matricular em várias turmas, e uma turma tem vários alunos; de cada matrícula guardamos a data e a nota final, que só é lançada no fim do curso."

 Individual. Pode consultar suas anotações, a cola de SQL e o glossário.

Enunciado completo para imprimir ou abrir no computador do aluno: listas/projeto-integrador.html

As perguntas do dono da TecnoCursos

  1. Quais cursos têm carga horária de 60 horas ou mais? Do mais caro para o mais barato.
  2. Liste todas as turmas com o nome do curso e o nome do instrutor, em ordem de data de início.
  3. Quais alunos estão em uma turma à sua escolha, com suas notas, da maior para a menor?
  4. Quais matrículas ainda estão sem nota? Mostre o nome do aluno e o nome do curso.
  5. Quais alunos nunca se matricularam em nenhuma turma?
  6. Para cada matrícula: aluno, curso, nota e a situação — 'Aprovado' (nota ≥ 6), 'Reprovado' (nota < 6) ou 'Cursando' (sem nota).

View: transforme a consulta 6 na view vw_Boletim e use-a para listar só os aprovados.

Seus dados precisam permitir todas as respostas: pelo menos um aluno sem matrícula, pelo menos uma matrícula sem nota, pelo menos uma nota abaixo de 6.
