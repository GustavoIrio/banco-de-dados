Os quatro problemas da planilha

1 · RedundânciaO CNPJ e a cidade do cliente se repetem a cada venda.
2 · Inconsistência"BS Serviços Automotivos" e "BS Serv. Automotivo" são o mesmo cliente? O computador acha que não.
3 · Falta de regrasNada impede escrever "dois" na quantidade ou deixar o vendedor vazio.
4 · Acesso simultâneoDois vendedores salvando o arquivo ao mesmo tempo: a última gravação apaga a outra.

Um banco de dados existe para resolver exatamente esses quatro pontos.

O que é um banco de dados

Um conjunto de dados estruturados, organizados conforme uma estrutura predefinida.

Ele precisa permitir quatro operações:

Inserir
cadastrar um cliente
Ler
listar as vendas de março
Alterar
mudar o preço de um produto
Excluir
remover um cadastro

"Estrutura predefinida" é a parte que a planilha não tem: primeiro dizemos que quantidade é um número inteiro, depois guardamos os dados.

Livro, cap. 5, p. 19.

De onde isso veio

QuandoO que aconteceu
Anos 1960IBM cria os bancos hierárquico e em rede. Para consultar, era preciso saber como os dados estavam gravados no disco.
1970Edgar F. Codd (IBM) propõe o modelo relacional: dados em tabelas que se relacionam.
1974Donald Chamberlin e Raymond Boyce (IBM) criam a linguagem SEQUEL, depois rebatizada SQL.
Anos 1980Bancos relacionais comerciais dominam o mercado.
Anos 2000+Internet e grandes volumes: surgem os bancos NoSQL (veremos na aula 7).

Mais de 50 anos depois, a ideia de Codd ainda é a base de quase todo sistema comercial. É nela que vamos focar.

Bloco 2 · 30 min

SGBD: quem toma conta do banco

O banco são os dados. O SGBD é o programa que fica na porta.

Banco de dados ≠ SGBD

Banco de dados: a coleção de dados (as tabelas da AutoNex).

SGBD — Sistema de Gerenciamento de Banco de Dados: o software que controla todo acesso a esses dados.

Ninguém mexe no arquivo direto. Toda leitura e toda escrita passa pelo SGBD.

O que o SGBD faz por nós

  • Impõe regras — quantidade é número, CNPJ não se repete. A aplicação não precisa conferir tudo sozinha.
  • Guarda a estrutura junto com os dados — os metadados (nomes das tabelas, tipos das colunas).
  • Controla quem acessa — usuário, senha e níveis de privilégio.
  • Permite acesso simultâneo — vários usuários e várias aplicações no mesmo banco.
  • Faz backup — copia o estado do banco para recuperar depois de um desastre.
SGBDs que você vai encontrar no mercado MySQL · MariaDB (o nosso) · PostgreSQL · Oracle · SQL Server · SQLite

Dado é coisa séria: segurança e ética

ConfidencialidadeSó quem tem autorização vê.
Quebra: entrar com a senha de outra pessoa.
IntegridadeO dado está correto e completo.
Quebra: alguém altera um valor indevidamente.
DisponibilidadeO dado está acessível quando preciso.
Quebra: sistema fora do ar.

Quem trabalha com banco de dados lida com informação sensível de outras pessoas. No Brasil, a LGPD (Lei 13.709/2018) define regras para tratar dados pessoais.

Regra prática do curso: não use dados reais de pessoas nos exercícios e nunca compartilhe sua senha do banco.

Livro, cap. 2 e 4, p. 11–17 · LGPD

Qual princípio foi quebrado?

 Em dupla, classifique cada caso: confidencialidade, integridade ou disponibilidade.

  1. Um estagiário exportou a lista de clientes com CNPJ e telefone e mandou para um amigo.
  2. O servidor do banco caiu na Black Friday e a loja ficou 3 horas sem vender.
  3. Um erro no sistema gravou o preço de todos os produtos como R$ 0,00.
  4. Um vendedor consegue ver o salário de todos os colegas na tela de relatórios.

1 — confidencialidade · 2 — disponibilidade · 3 — integridade · 4 — confidencialidade.

O modelo relacional

Tudo é tabela. Mas tabela com regras.

Anatomia de uma tabela

Produtos

No dia a diaNome formalO que é

Livro, cap. 7, p. 24–25 (Elmasri & Navathe, 2011).

Três regras que diferenciam tabela de planilha

  1. Cada coluna tem um domínio. Se Estoque é inteiro, "dois" é recusado.
  2. Cada célula guarda um valor só — um valor atômico. Nada de dois telefones na mesma célula.
  3. Não existem duas linhas idênticas. Alguma coluna (ou combinação) precisa identificar cada linha. Aqui é o ProdutoID.
Notação de esquema Produtos(ProdutoID, Nome, Descricao, Preco, Estoque)
Nome da relação, lista de atributos, identificador sublinhado. O grau da relação é o número de atributos: aqui, 5.

Livro, cap. 7, p. 25.

Bloco 4 · 45 min

Seu primeiro SQL

Quatro comandos. No fim, um banco com dados dentro.

Passo 1 — criar o banco

No phpMyAdmin, clique na aba SQL (sem nenhum banco selecionado), digite e clique em Executar:

CREATE DATABASE AutoNex;

O banco aparece no painel da esquerda. Clique nele para que os próximos comandos rodem dentro dele.

Como o SQL é escrito
  • Todo comando termina com ponto e vírgula.
  • Palavras do SQL em MAIÚSCULAS é convenção, não obrigação. Ajuda a ler.
  • Textos vão entre aspas simples: 'Pneu X'.

Livro, cap. 11.1, p. 51.

Passo 2 — criar a tabela

CREATE TABLE Produtos (
    ProdutoID INT PRIMARY KEY,
    Nome      VARCHAR(100),
    Descricao TEXT,
    Preco     DECIMAL(10,2),
    Estoque   INT
);

Cada linha dentro dos parênteses é uma coluna: nome, depois o tipo (o domínio).

TipoGuarda
INTnúmero inteiro
VARCHAR(100)texto de até 100 caracteres
TEXTtexto longo
DECIMAL(10,2)número com 2 casas decimais

PRIMARY KEY: esta coluna identifica cada linha e não pode repetir. Aula 3 inteira sobre isso.

Depois de executar, abra a aba Estrutura da tabela e confira as colunas.

Livro, cap. 11.1, p. 51 · MariaDB: CREATE TABLE

Passo 3 — inserir dados

INSERT INTO Produtos (ProdutoID, Nome, Descricao, Preco, Estoque)
VALUES (1, 'Correia de distribuição',
        'Correia dentada que sincroniza o motor', 512.05, 200);

INSERT INTO Produtos (ProdutoID, Nome, Descricao, Preco, Estoque)
VALUES (2, 'Pneu X 205/55 R16', 'Pneu de alta performance', 350.00, 100);
Atenção Decimal em SQL usa ponto: 512.05.
A vírgula separa um valor do outro.
Leia assim "Insira em Produtos, nestas colunas, estes valores." A ordem dos valores segue a ordem das colunas.

Livro, cap. 11.2, p. 55 · MariaDB: INSERT

Quebre as regras de propósito

 Execute cada comando e leia a mensagem. Anote: funcionou? Por quê?

-- A
INSERT INTO Produtos (ProdutoID, Nome, Descricao, Preco, Estoque)
VALUES (2, 'Filtro de óleo', 'Filtro para motores 1.0 a 2.0', 38.90, 500);

-- B
INSERT INTO Produtos (ProdutoID, Nome, Descricao, Preco, Estoque)
VALUES (3, 'Filtro de óleo', 'Filtro para motores 1.0 a 2.0', 38.90, 'quinhentos');

-- C
INSERT INTO Produtos (ProdutoID, Nome, Descricao, Preco, Estoque)
VALUES (3, 'Filtro de óleo', 'Filtro para motores 1.0 a 2.0', 38.90, 500);

A falha: já existe o ProdutoID 2 (entrada duplicada para a chave primária).
B falha: 'quinhentos' não é um inteiro (valor incorreto para a coluna Estoque).
C funciona. Era isso que a planilha não fazia: o SGBD recusou os dados errados.

Revisão relâmpago

1. Qual é o papel do SGBD?

  1. Guardar os dados em uma planilha compartilhada
  2. Controlar todo acesso aos dados do banco
  3. Desenhar as telas do sistema para usuário
Toda leitura e escrita passa pelo SGBD; é ele que aplica as regras.

2. No modelo relacional, uma linha da tabela se chama…

  1. atributo
  2. domínio
  3. tupla
Tabela = relação, coluna = atributo, linha = tupla, tipo = domínio.

3. Por que o INSERT com estoque 'quinhentos' foi recusado?

  1. Porque a chave primária já existia
  2. Porque faltou o ponto e vírgula
  3. Porque o valor foge do domínio
A coluna foi declarada como INT; o SGBD só aceita valores desse domínio.
